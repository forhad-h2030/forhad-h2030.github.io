RUS — Fun4All I/O Interface for E1039

A C++ package that integrates a dependency-free ROOT-based I/O format (RUS) into the Fun4All framework used by the SpinQuest (E1039) experiment at Fermilab. The interface allows users to register RUS files directly in Fun4All macros — with no dynamic library dependencies — to drive reconstruction, simulation, or event extraction pipelines. The output files produced by this interface are consumed by downstream analysis tools, including the QTracker ML-based muon track reconstruction pipeline.

How It Works

Input Manager — Fun4AllRUSInputManager

Reads RUS-format ROOT files and converts the stored data into E1039 data structures within the Fun4All event loop. Handles run metadata, spill information, FPGA and NIM trigger data, detector hits, and optional MC truth tracks. Multi-file synchronization is managed via Fun4All's GetSyncObject/SyncIt interface, ensuring consistent event ordering across input files.

Output Manager — Fun4AllRUSOutputManager

Writes Fun4All event data to RUS-format ROOT files with tuned I/O parameters: compression level 5, 64 kB basket size, and auto-flush every 2,500 entries for efficient sequential read performance. Automatically detects whether MC truth track nodes are present at runtime and enables the corresponding output branches — no recompilation required to switch between data and simulation modes.

Usage in a Fun4All Macro

// Register output
Fun4AllRUSOutputManager* tree = new Fun4AllRUSOutputManager();
tree->SetTreeName("tree");
tree->SetFileName("RUS_out.root");
se->registerOutputManager(tree);

// Register input
Fun4AllRUSInputManager* in = new Fun4AllRUSInputManager("RUS");
in->fileopen("RUS_input.root");
se->registerInputManager(in);

Downstream Use — QTracker

The RUS output files are the primary data source for QTracker, a deep learning pipeline for muon track reconstruction in SpinQuest. QTracker reads the detector hit arrays from RUS ROOT files, runs a TrackFinder neural network to predict muon hit patterns, refines hits against real detector geometry, and predicts muon momenta — writing reconstructed results back to ROOT files for physics analysis.

Technical Highlights

  • No dynamic dependencies — self-contained ROOT TTree format is portable across HPC environments (Rivanna, FermiGrid) without shared library requirements
  • Tuned I/O performance — compression level 5, configurable basket size and auto-flush for optimized throughput on large datasets
  • Explicit buffer management — vector branch containers are reset between events to prevent memory accumulation in long runs
  • Runtime MC/data switching — output manager detects truth track nodes automatically; no recompilation needed between data and simulation workflows
  • Fun4All synchronization — implements GetSyncObject/SyncIt for correct event ordering when chaining multiple input files
