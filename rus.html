RUS: Fun4All I/O Interface for E1039

A C++ package that integrates a dependency-free ROOT-based I/O format into Fun4All, enabling portable reconstruction, simulation, and event-extraction workflows.

Architecture

How it works

Users can register RUS files directly in Fun4All macros with no dynamic library dependencies. The same interface supports real data, simulation, reconstruction, and downstream event extraction.

Fun4AllRUSInputManager

Reads RUS-format ROOT files and converts run metadata, spill information, trigger data, detector hits, and optional MC truth tracks into E1039 data structures.

Fun4AllRUSOutputManager

Writes event data with tuned compression, basket size, and auto-flush settings while detecting MC truth nodes automatically at runtime.

// Register output
Fun4AllRUSOutputManager* tree = new Fun4AllRUSOutputManager();
tree->SetTreeName("tree");
tree->SetFileName("RUS_out.root");
se->registerOutputManager(tree);

// Register input
Fun4AllRUSInputManager* in = new Fun4AllRUSInputManager("RUS");
in->fileopen("RUS_input.root");
se->registerInputManager(in);

Downstream workflow

QTracker integration

RUS output files are the primary data source for QTracker, a deep-learning pipeline for muon-track reconstruction in SpinQuest. QTracker reads detector-hit arrays from RUS ROOT files, predicts muon hit patterns, refines hits against detector geometry, estimates muon momenta, and writes reconstructed results back to ROOT for physics analysis.

Implementation

Technical highlights

  • No dynamic dependencies. The self-contained ROOT TTree format is portable across Rivanna, FermiGrid, and other HPC environments.
  • Tuned I/O performance. Compression level 5, configurable basket size, and auto-flush optimize sequential throughput on large datasets.
  • Explicit buffer management. Vector branch containers reset between events to prevent accumulation during long runs.
  • Runtime MC/data switching. Truth-track nodes are detected automatically, without recompilation.
  • Fun4All synchronization. GetSyncObject and SyncIt maintain event ordering when chaining input files.
